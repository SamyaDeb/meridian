## Checklist results (no finding)
- **Reentrancy / CEI:** every vault entry point (`deposit`, `mint`, `withdraw`, `redeem`, `rebalance*`, `enterHedge`, `exitHedge`) and both hedger functions are `nonReentrant`. External calls go only to immutable, deploy-verified contracts (CH, OB, hedger, WMON), and the constructor checks the wiring (`collateralToken`, `orderBook`, `quoteToken`). ERC-4626 `_withdraw` burns before transferring. The hedger pulls exact amounts, forwards the whole output plus leftovers, and holds nothing between calls.
- **Approvals:** the vault uses exact `forceApprove`, fully consumed by the hedger or CH. The hedger resets the Kuru and Flow approvals to 0 after each call.
- **Kuru route:** `minOut` always comes from the oracle index ∓ `maxSlippage` (`_baseFor`, `_sellSpot`) and never from the keeper. The output is measured by balance delta, so a route that pays someone else reverts `SlippageExceeded`. Native MON is wrapped. The perp leg's limit tick also comes from the index (bids round down, asks round up).
- **ERC-4626:** offset 12 (1e12 virtual shares per 1 virtual asset unit) ⇒ a donation attack costs ≈ 1e12× what it steals (`test_inflationAttack`). The 5 bps fee goes to the remaining holders; `previewWithdraw` rounds up; `maxDeposit` = cap − NAV.
- **Oracle:** staleness (a future publishTime counts as fresh, bounded by Pyth's signatures), `expo` ∈ [−18, 0], conf ≤ 1%, price ≤ 0 ⇒ Invalid, exact deviation test without division, and the view never reverts on a feed failure. When the oracle fails, the CH freezes funding and keeps the last good index (`indexPrice()`), so vault NAV uses the last good index: price-neutral when hedged.
- **Access control:** vault `onlyOwner` for params/keepers/providers and `onlyKeeper` for rebalances; hedger `setVault` is one-shot and owner-only; all param setters are bounded (`_storeParams`, `_setOracleParams`). The skew-provider list is capped at `MAX_BATCH`. No unbounded loops.
- **Economic:** NAV is at the oracle index, so trading on Kuru or Meridian can't move it. Sandwiching a rebalance is bounded by `maxSlippage` × one slice per leg (≤ 0.5% × 2,500 AUSD; ≤ 0.5% × ≈ 1,140 AUSD at the launch cap). The skew-rule manipulation is A-08.
